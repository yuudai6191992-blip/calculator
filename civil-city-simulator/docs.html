1. コンセプト

「SimCity × Cities: Skylines × 建設コンサルタント × 都市計画 × 防災 × デジタルツイン」

Civil City Simulator は、プレイヤーが市長ではなく建設コンサルタントとして、 都市の課題を診断し、インフラ整備・都市計画・防災対策を通じて街を改善していくシミュレーションゲームです。

対象ユーザー

  • 🏢 建設コンサルタント —— 実務知識の応用・プロポーザル資料作成
  • 🏛️ 自治体職員 —— 都市計画・防災の教育ツール
  • 🎓 学生 —— 都市工学・土木計画の学習支援
  • 📐 都市計画担当者 —— 政策シミュレーション・民間意見集約

主な特徴

🎮 ゲーミング性

単純な建設では不十分。人口・税収・幸福度・防災・CO2など複数の指標で評価される。

📊 リアル都市計画

老朽化・LCC・B/C・PPP/PFI・ハザードマップなど、実務で使う概念を搭載。

🤖 AI診断

「北側は病院不足です」「橋梁更新を推奨します」など、建設コンサルタント視点の提言を生成。

3️⃣ フォトリアル3D

Three.jsによる物理ベースレンダリング。実写級の3D都市表示。

2. ゲームシステム

2.1 マップ構成

  • グリッドサイズ： 20×20セル
  • 各セル： 1つの建物・施設・地形を持つ（例：住宅、道路、河川など）
  • 河川： マップ東側を蛇行しながら縦断（自動生成、撤去不可）
  • 山地エリア： マップ北側2行（土砂災害警戒区域）

2.2 ターンシステム

操作 説明 速度
手動進行 「次のターン」ボタンで1ターンずつ進める 任意
自動進行（1倍速） 3秒ごとに自動でターン進行 3秒/ターン
自動進行（2倍速） 1.5秒ごとに自動でターン進行 1.5秒/ターン

1ターン = 想定1四半期（3ヶ月）

2.3 予算・収支システム

  • 初期予算： 2,000M（百万円）
  • 収入源：
    • 商業施設の税収（建物により異なる）
    • 工業施設の税収
    • 人口に基づく住民税
  • 支出源：
    • 各施設の維持管理費（毎ターン）
    • 老朽化による維持費増加
    • インフラ更新費
  • 破産条件： 予算が-1,000Mを下回ると警告を表示

2.4 老朽化・ライフサイクルコスト（LCC）

すべての建物・インフラは時間経過で老朽化します：

  • 老朽化の進行： ターンごとに age が加算される
  • 築30ターン以上で「老朽施設」： 維持費が増加（最大2倍）
  • 更新のメリット： 築30年以上の施設は新設費の70%で更新可能
  • LCC計算： 建設費 + 維持管理費累計 + 更新費累計
💡 建設コンサルタント的な考え方： 最安の建設ではなく、生涯費用（LCC）を最小化する戦略が重要です。 定期更新で古い施設のリプレイスメント計画を立てましょう。

4. KPI（15評価指標）

ゲームは15個のKPI（重要業績評価指標）で都市を総合評価します。

4.1 経済指標

KPI 計算方法 目安
人口 住宅数 × 10 × 幸福度係数 × 交通係数 2,000人以上が目標
税収 商業・工業の税収 + 住民税（人口×税率） 維持費を上回る必要あり
維持管理費 各施設の維持費 × (1+老朽化係数) 税収を超えると赤字
B/C（費用便益比） 経済効果 ÷ (総投資額+維持費累計) 1.0以上が理想

4.2 社会指標

KPI 計算方法 目安
幸福度 基準50 + 施設効果 - 未接続/渋滞/災害ペナルティ 60以上が健全
交通利便性 住宅の道路・駅・バス停アクセス平均 60以上で高利便性
渋滞度 容量超過道路の割合 10%以下に抑える
地価指数 基準100 + 周辺施設効果 - 老朽化 120以上で上昇
公共施設充足率 公共施設数 ÷ 必要数（人口100人あたり1施設） 100%が満足度を最大化

4.3 環境・防災指標

KPI 計算方法 目安
CO2 工業・人口による排出 - 公園による吸収 低いほど良い
災害リスク 浸水40% + 土砂25% + 避難体制35%の加重平均 20%以下が安全
浸水リスク 河川2セル以内の無防備建物割合 - 調整池効果 堤防・調整池で軽減
土砂災害リスク 山地エリア(北側2行)の開発密度 山地開発は抑止が吉
老朽化率 築30ターン以上の建物割合 20%以下に保つ
🎯 総合評価： 各KPIが及第点(一般的には60%以上)に達すると、AI診断で「都市として成立している」と評価されます。

5.3 UI パネル

左パネル：建設メニュー

  • 15種類の建物・施設アイコンを表示
  • クリックで選択状態になり、マップをクリックして配置
  • 選択状態のアイコンは背景が強調表示

中央：3D マップ表示

  • フォトリアルな3D都市を表示
  • 建物・道路・自動車・水面などをリアルタイム描画
  • ハザードマップ表示時は浸水・土砂災害リスク区域を色表示

右パネル：KPI ダッシュボード

  • 15個のKPI数値とゲージを表示
  • AI診断の提言を表示（毎ターン更新）
  • 破産警告やイベント通知

下部：イベントログ

  • 建設・撤去・災害発生などの履歴を時系列表示
  • 赤色：危険通知、黄色：警告、緑色：成功

5.4 特殊機能

  • クリックで ON/OFF を切り替え
  • 浸水リスク区域を青色で表示

  • 防災計画の策定に有用

🏛️ PPP/PFI 政策メニュー

  • Park-PFI：公園維持費50%削減（導入費300M）
  • PPP/PFI包括委託：公共施設維持費30%削減（導入費500M）

6. 技術仕様

6.1 技術スタック

  • 言語： HTML5 + CSS3 + JavaScript (ES6 Modules)
  • フレームワーク： Vanilla JS（フレームワーク非依存）
  • 3D描画： Three.js 0.165.0（リポジトリに同梱）
  • 外部依存： なし（CDN不使用、オフライン動作対応）

6.2 実行環境

ES Modules を使用しているため、ローカルサーバーで起動してください（ファイルスキームでは動作しません）。

# 方法1: Python python3 -m http.server 8000 # 方法2: Node.js npx serve . # 方法3: その他（Live Server など）

ブラウザで http://localhost:8000 を開いてください。

6.3 推奨環境

項目 推奨
ブラウザ Chrome 90+, Firefox 88+, Safari 14+, Edge 90+
解像度 1920×1080 以上（1600×900 以上で動作）
GPU メモリ 2GB 以上推奨（1GB で動作）
RAM 4GB 以上（2GB で動作）

6.4 JSON セーブ形式

将来の実装予定として、ゲーム状態は JSON 形式でシリアライズ可能です：

{ "turn": 50, "budget": 15000, "grid": [ [{ "x": 0, "y": 0, "type": "empty" }, ...], ... ], "policies": { "parkPFI": false, "pppPFI": true }, "kpi": { "population": 2500, "revenue": 800, ... } }

7.3 1ターンの処理フロー

nextTurn() 処理順序: 1. transportation.processTurn() → 交通・渋滞・利便性 2. infrastructure.processTurn() → 水道・老朽化・更新 3. disaster.processTurn() → 災害判定・リスク計算 4. applyPolicies() → PPP/PFI 効果 5. simulation.nextTurn(extras) → 人口・幸福度・経済 6. refreshUI() → ダッシュボード更新

7.4 データフロー

  • ゲーム状態： map.grid[y][x] に各セル情報を持つ（単一の真実の源）
  • 各セル構造： { x, y, type, age, level }
  • サブシステム結果： extras オブジェクトで simulation に渡される（疎結合）
  • KPI 一元管理： simulation.kpi に全15指標をまとめて管理

7.5 将来拡張の設計指針

GIS 統合（OpenStreetMap / PLATEAU）

グリッドを緯度経度に変換するレイヤーを追加すれば、MapLibre GL JS のタイルマップ上へ投影可能。 data/sample-city.json の形式が実データ変換の受け皿として機能。

3D 表示（Three.js）

map.render() は renderer3d へ委譲する薄いラッパー。 他の3Dエンジン（Babylon.js など）への置き換えが容易。

バックエンド（Supabase / Node.js）

serialize() の出力をそのまま Supabase に保存。 リアルタイムデータはターン処理の extras に注入する形で統合。

9. よくある質問（FAQ）

ゲーム全般

Q: どうやって始めるの？

A: まずは道路を敷きます。左メニューから「道路」を選び、マップをクリック。 その後、道路沿いに住宅を配置して人口を増やします。人口が増えると税収が増え、 商業施設や公共施設を建設する資金ができます。

Q: 何を目指すゲーム？

A: 15個のKPI指標をすべて及第点(60%以上)に達させることが総合ゴールです。 ただし、ターン数の制限はないため、自分のペースで楽しめます。

Q: 破産したらどうなる？

A: 予算が-1,000Mを下回ると警告が表示されます。 古い建物を撤去したり、PPP/PFIで維持費を削減することで対応できます。 完全な破産状態でもゲームオーバーにはなりません。

建設・管理

Q: 道路はどのように配置すればいい？

A: 格子状に敷くのが基本です。縦・横に規則的に配置すると、 すべての建物が道路に接続しやすく、交通利便性が向上します。

Q: 公園や病院はいくつ必要？

A: 「公共施設充足率」のKPIで確認できます。 人口100人あたり1施設が目安です（例：人口1,000人なら10施設）。

Q: 橋梁はどこに建設する？

A: 河川上のみに建設できます。青い水セルをクリックして「橋梁」を選択。 これで河川の向こう岸に建物を建設できるようになります。

防災・老朽化

Q: ハザードマップって何？

A: 🗺️ボタンで表示切替。青は浸水想定区域、黄は土砂災害警戒区域です。 これらのエリアに堤防・調整池・避難所を配置することで、災害リスクを軽減できます。

Q: 老朽化した建物はどうする？

A: 築30ターン以上の建物は「老朽施設」となり、維持費が増加します。 撤去して新しい建物を建設するか、老朽化の進行を受け入れるかは戦略次第です。

Q: 堤防はどこに建設すればいい？

A: 河川沿いに建設します。河川から2セル以内の建物が浸水リスクを持つため、 河川の手前に堤防を敷くことで被害を軽減できます。

経済・政策

Q: PPP/PFI って何？

A: 民間活力を導入して、公共施設の維持費を削減する政策です。 🏛️ボタンから導入でき、Park-PFI（公園50%削減）と PPP/PFI包括委託（施設30%削減）があります。

Q: B/C が1.0以上にならない

A: B/C = 経済効果 ÷（総投資額+維持費累計）です。 税収を増やす（商業・工業）、または投資を絞る（無駄な建物を避ける）ことで改善します。

技術的な質問

Q: オフラインで動作する？

A: はい。ローカルサーバーを起動すれば、インターネット接続不要です。 python3 -m http.server 8000 で起動できます。

Q: セーブ・ロード機能は？

A: 現在は実装していません。将来的に Supabase や LocalStorage への保存を検討しています。

Q: モバイル対応？

A: タッチ操作で基本的な操作は可能ですが、UI が小さいため、 タブレット（1920×1080以上の大画面）での利用を推奨します。
