# Civil City Simulator - 仕様書

## 1. コンセプト

「SimCity × Cities: Skylines × 建設コンサルタント × 都市計画 × 防災 × デジタルツイン」

プレイヤーは**市長ではなく建設コンサルタント**として、都市の課題を診断し、
インフラ整備・都市計画・防災対策を通じて街を改善していく。

### 対象ユーザー
- 建設コンサルタント
- 自治体職員
- 都市計画を学ぶ学生
- 都市計画担当者

## 2. ゲームシステム

### 2.1 マップ
- 20×20のグリッドマップ
- 各セルは1つの建物・施設・地形を持つ
- 河川が自動生成される（マップ東側を縦断）
- マップ北側2行は山地エリア（土砂災害警戒区域）

### 2.2 建物一覧

| 建物 | 建設費 | 維持費/T | 主な効果 |
|------|-------|---------|---------|
| 住宅 | 100 | 5 | 人口+10 |
| 商業施設 | 200 | 10 | 税収+30、雇用+8 |
| 道路 | 30 | 2 | 接続基盤 |
| 公園 | 80 | 3 | 幸福度+5、地価+10 |
| 工業施設 | 300 | 15 | 税収+50、CO2+10 |
| 病院 | 500 | 30 | 幸福度+8 |
| 学校 | 400 | 25 | 幸福度+6 |
| 消防署 | 350 | 20 | 災害リスク軽減 |
| 駅 | 800 | 40 | 交通利便性+40 |
| バス停 | 100 | 5 | 交通利便性+20 |
| 橋梁 | 500 | 25 | 河川横断（水域のみ建設可） |
| 堤防 | 200 | 8 | 浸水リスク軽減 |
| 調整池 | 400 | 15 | 洪水リスク-8%/基 |
| 避難所 | 300 | 10 | 避難カバー率向上 |
| 防災公園 | 250 | 8 | 公園+避難所の複合機能 |

※金額単位は百万円（M）

### 2.3 ターンシステム
- 手動進行（次のターンボタン）
- 自動進行（1倍速: 3秒/ターン、2倍速: 1.5秒/ターン)
- 1ターン = 想定1四半期

### 2.4 KPI（評価指標）

| KPI | 計算方法 |
|-----|---------|
| 人口 | 住宅数 × 10 × 幸福度係数 × 交通係数 |
| 税収 | 商業・工業の税収 + 住民税（人口×税率） |
| 幸福度 | 基準50 + 施設効果 - 未接続/渋滞/災害ペナルティ |
| CO2 | 工業・人口による排出 - 公園による吸収 |
| 維持管理費 | 各施設の維持費 ×（1+老朽化係数） |
| 交通利便性 | 住宅の道路・駅・バス停アクセス平均 |
| 渋滞度 | 容量超過道路の割合 |
| 災害リスク | 浸水40% + 土砂25% + 避難体制35%の加重平均 |
| 浸水リスク | 河川2セル以内の無防備建物割合 - 調整池効果 |
| 土砂災害リスク | 山地エリアの開発密度 |
| 老朽化率 | 築30ターン以上の建物割合 |
| 地価指数 | 基準100 + 周辺施設効果 - 老朽化 |
| B/C | 経済効果 ÷（総投資額+維持費累計） |
| 公共施設充足率 | 公共施設数 ÷ 必要数（人口100人あたり1施設） |

### 2.5 老朽化とLCC
- すべての建物はターン経過で老朽化（age加算）
- 老朽化により維持費が増加（最大2倍）
- 築30ターン以上で「老朽施設」となり更新推奨
- 更新費は新設費の70%
- LCC = 建設費 + 維持管理費累計 + 更新費累計

### 2.6 災害システム
- **豪雨・洪水**（確率4%/ターン）: 河川近傍の堤防なし建物が被害
- **地震**（確率2%/ターン）: 老朽建物ほど倒壊しやすい
- **土砂災害**（確率2%/ターン、山地開発時のみ）: 山地エリアの建物が被害
- ハザードマップ表示機能（浸水想定区域・土砂災害警戒区域）

### 2.7 政策システム（PPP/PFI）
- **Park-PFI**: 導入費300M、公園維持費50%削減
- **PPP/PFI包括委託**: 導入費500M、公共施設維持費30%削減

### 2.8 AI都市診断
KPIとマップ配置を分析し、建設コンサルタント視点の提言を生成:
- 財政診断（赤字・維持費過大）
- 地域別施設不足診断（「北側は病院不足です」）
- 交通診断(渋滞・利便性)
- インフラ老朽化診断（橋梁更新推奨）
- 防災診断（浸水リスク・避難所カバー率）
- PPP/PFI導入提案

## 3. 技術仕様
- HTML5 + CSS3 + JavaScript (ES6 Modules)
- 外部ライブラリ不使用（Vanilla JS）
- ブラウザで直接動作（要ローカルサーバー: ES Modules使用のため）

## 4. 将来拡張の設計考慮
- マップデータはJSON形式でシリアライズ可能（GIS連携準備）
- 座標系はグリッドベースだが、GeoJSON変換レイヤーを追加可能
- OpenStreetMap / PLATEAU / 国土数値情報の取込みインターフェース
- Three.js / MapLibre による3D・地図表示への移行パス
- Supabase によるセーブデータ共有・ランキング
